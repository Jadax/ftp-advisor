# FTP Advisor

Single-file Tampermonkey userscript: `ftp-advisor_user.js` (~10.6k lines, one IIFE). Tactical/scouting advisor for fromthepavilion.org (cricket sim). Team auto-detected per install (`getTeamId()`). Public repo: github.com/Jadax/ftp-advisor. No build step, no test suite, no headless access to the live game. Detailed per-version history: `git log` (CLAUDE.md records only current, load-bearing constraints).

## Invariants (each exists because breaking it caused a real reported bug)
- **Age parsing**: every age scrape goes through `parseGameAge` (handles "25.05" tables and "25y5w" panels; week is 1-BASED within the age-year, so "20.14" = 20.93, still 20). Per-year table lookups use `ageYears` (floor = the displayed year), NEVER `Math.round` (zero such sites — keep it zero). Simulations advance age `(week-1)/14` per week — 14 weeks per age-year, never 52. `weeksToAge` has a `-1e-9` guard before `ceil` (float drift at exact boundaries).
- **Role detection**: one canonical `getPrimarySkillInfo()` (keeping counts as primary at >=4 and best; 0/0 defaults to batting — a no-data player must not read as a bowler). No ad hoc `Math.max(batting,bowling)` anywhere.
- **Hard filters gate on "known"**: transfer-list rows have `wage: 0, experience: 0, rating: 0` until the per-player fetch. Any min-check on a post-fetch-only field must be gated `known: (v||0) > 0`, or every candidate silently fails and results go empty.
- **Squad cache self-heal**: `fetchAllData` force-refetches when the cache is null, empty, all-zeroed, single-row-zeroed, or one-role-group-missing (youth-only/senior-only); the merge keeps last-known-good per group when a fresh fetch returns 0 for that group. Don't weaken these — an empty cache once stuck permanently and produced weeks of "no current SENIOR X" false gaps.
- **Security**: ALL scraped/pasted names+talents are `escapeHtml()`'d AT THE PARSER (5 name parsers, 3 talent parsers, ground scrape, both scorecard paths). Names are chosen by other users; this script interpolates them into innerHTML at ~80 sites — unescaped = script execution in the authenticated page origin. Add escaping to any NEW scrape point; never rely on render-site escaping. Match-history TEAM names stay raw deliberately (matched against raw page text, never rendered raw).
- **Bowling allocator**: FTP ends ALTERNATE overs — a spell "1st Over: 16, # 3" covers 16,18,20. All expansion goes through `expandSpellOvers` (start + 2i); `validateSpellCoverage` must pass (every over exactly once, nothing past the innings end) — the game rejects otherwise. Per-bowler caps `MAX_OVERS_PER_BOWLER = {OD:10, YOD:8, T20:4, YT20:4}` (manual-confirmed; the 10-overs U20 match was a World Cup game, not a contradiction). Min spell 2 OD / 1 T20; no consecutive overs; drinks-break split merges a bowler's same-end spells BEFORE deciding candidacy (max 2 pieces/bowler); allocator is deterministic — zero `Math.random` anywhere, keep it zero (non-determinism = recommendations flapping between visits). Lives within an under-resourced-squad backstop (size 5 OD/YOD overflows a bowler by ≤2 with a warning to recruit; capacity-forced configs `nBowlers × cap < overs` may over-run too — any plan must). **Hard caps vs heuristics**: `fixEndTotal` strategies run 1 (fatigue-clamped extend) → 2/2.5 (new spell ≥ min) → 2.75 (extend keeping cap+maxPerSpell, relax fatigue only) → 2.9 (deficit < min: borrow `k = minPerSpell − deficit` from an existing spell, open a fresh min-size spell for a bowler with room — net −deficit, so stranded 1-over remainders never fall through) → 3 (over-cap last resort, warns "recruiting/training another bowler"). Strategy 3 firing on a squad with `bowlers × cap ≥ overs` is a BUG (was the reported Alfred Close 11-overs case). **Adjacency repair is OVER-based**: list-adjacency ⇔ over-adjacency only under strict alternation — cross-end swaps and tails break it, so `fixAdjacency` dry-run-numbers (`numberRun` mirrors `numberAndTactics`, side-aware `breakOver`) and relocates on real `(o, o+1)` clashes; never "fix" adjacency by comparing list neighbours. **Match length and caps come from the orders page itself when present** (`scrapeMatchOrderSettings`: `_oversPerEnd`/`_minSpellLength`/`_maxSpellLength` in inline script, overs grids as fallback) — friendly comps have no format word in their League cell (a "WCSL2" game is 40 overs, cap 8, but league-text alone would default to OD/50); scraped values override the per-format tables; overs-only format inference 20→T20 / 40→YOD / else OD.
- **Determinism**: same inputs must always produce the same recommendation (see above).
- **Tactics scoring** (v8.101, from a replayed real match): fatigue is MULTIPLICATIVE via `FATIGUE_MULTIPLIER` (workbook Form-Exp tab, mapped by NAME: rested 1.00 … listless .59, exhausted .52; the sheet's extra "rest .98" row is the grid abbreviation of rested, not a level) on bat/bowl/keep/captain scores — never an additive `fatigue*k` (that let a Listless captain and an Exhausted bowler into an XI). Technique SCALES the primary (`techniqueScaledPrimary`, manual: technique = consistency of the primary) — never additive (a Dreadful bowler with Reliable technique outranked the best spinner). Every additive term (core, T20 power, flat talent bonuses) is summed BEFORE the multipliers (form/exp/fatigue/pitch/weather/home) — added after, they dominated on extreme days (Sticky×Humid scales cores to ~20%). LH/RH and seam/spin variety are TIEBREAKS within `VARIETY_TOLERANCE` (manual: "small"/"relatively minor"; "often still advisable to select the bowlers best suited to the pitch and weather, regardless of style") — never quotas. Keeper: among keepers within tolerance, the one whose bowling is lost least. Sticky has no pace bonus (manual: favours ALL bowlers). Friendlies (`context.isFriendly`, League text "friendly") run everyone at rested (manual). `analyzeOpposition(…, isYouthMatch)` profiles the age group that can actually play (seniors are barred from youth matches).
- **Expensive sims**: `simulateAdaptiveTrainingPlan` re-runs `recommendTraining` per simulated week — any new loop caller passes `{ skipProjection: true }`. `computePlayerCeiling`/`computeOverallRating` results are precomputed once per candidate per render pass and stored on the player object (`_ceilingResult`, `_dynastyCeiling`, `_overallRating`) — read them back, don't re-run.
- **One horizon, one scale**: Dynasty chip, Player Advisor Dynasty line, and Overall Rating all consume `computePlayerCeiling(..., 25)` — the same projection, so they can't disagree. Near-term horizon (to-20 youth / 2yr senior / 1yr 30+) feeds the Training Potential panel and "Projected at 20". Projections use the CURRENT academy (`ACADEMY_RAMP_YEARS` = 0 since v8.120 — the user's method and the workbook's) and no extra calibration (v8.106-v8.119 `YOUTH_PROJECTION_CALIBRATION` removed). Academy speed = `ACADEMY_SPEED[levelNum]` from the Academy page's LEVEL (24h cache) — the page's 'Training Efficiency %' is overcrowding only (manual) and is applied per squad via `squadSizeForPlayer`, never multiplied in as the speed (v8.112).
- **Verdict words**: transfer-card verdict derives from `_overallRating.label` (can't contradict the ★ badge); legacy `evaluateTransferTarget` verdict drives only the hard-filter part of `isWorthShowing` (poor/weak = failed base/minimums) and sort.
- **Same age, same horizon** (v8.102, user: "a 26 year old can't be compared to a 21 year old"; he buys 20-21yos to develop): every player-vs-player judgement compares to-25 projections (`projectedSkillAt25`; 25+ project to themselves) — `comparePlayerToSquadPeers` (same role AND same age group: youth vs youth, senior vs senior), the senior transfer filter (shown = passes hard filters AND projects above a current same-role senior, or fills a gap — the old "legacy ELITE + outranks on CURRENT skill" hid every development signing), `computeRoleSurplus` depth ranking, senior sell "primary below standard" for under-24s, youth-sell "below weakest senior". Never compare current skill across ages. Candidates are projected BEFORE the filter (`computeCandidateRating` runs inside the evaluate map); the after-fetch re-eval recomputes rating then compare.
- **Youth sell list**: role-aware skill (primary/tech/fielding), experience shortfall is light (grows by playing), only role-aligned Gifted/Skilled + Sturdy protect, the best 11 youths (youth XI — prize money/sponsorship ratings) aren't penalised for not beating a senior and sell after non-XI prospects, and "sell now" is capped at youths − 12 (manual auto-draft floor) with the rest listed as replace-via-weekly-recruits.
- **Ground pitch**: `recommendPitchForSquad(…, paceMix)` — a seam-dominant squad whose top-3 MEDIUMS out-bowl its top-3 F/FM by ≥0.5 gets Green, not Uneven (manual: Uneven favours fast/fast-medium, Green "particularly medium pace"; Uneven handed the reported Chennai T20 to their rf). Green paceBonus 0.9 (seam 1.25) so tactics favour mediums there too.
- **Youth curve is time-aware**: `evaluateYouthDevelopment` marks a below-target trainable stat `behind` only if it can't reach the target before the displayed age increments; reachable = `catching-up`. Weeks-to-close summed across all below-target trainable stats vs weeks left (2+ behind is naturally infeasible). Experience is flat-behind (grows by playing).
- **Scout base**: `AGE_SCOUT_THRESHOLDS` is a hard filter (verbatim user data — don't loosen without new user data). Universal 25k rating floor every age 16-27. `YOUTH_DEV_CURVE` = the REALISTIC curve the user chose (2026-11): minimum 16 Avg / 17 Reas / 18 Capab / 19 Reli,Reli,Capab / 20 Accom,Accom,Reli (+ Ordinary End/Exp), good line one step up (= the community curve shifted). Every step and 16->20 must stay trainable for a typical player (half a level in) at Excellent with the workbook arithmetic — `curvetest.js` enforces it. The community curve's 18->19 (Capable->Accomplished) jump is not trainable in a year.
- **Talents**: source of truth is `rules.htm?rulespage=playerother` — re-quote before changing talent logic. Prodigy youth-only; Seam/Spin Specialist are BATTING matchup talents (gated to batting primary + opponent's bowling mix); triggered delivery talents are real but unquantified (conservative flat bonuses); mismatched role talents contribute nothing AND warn.
- **Training program identities**: Fitness is endurance-primary and Strength is power-primary (`TRAINING_BASE_RATES` = Fitness `{endurance:200, power:70}`, Strength `{endurance:65, power:190}` — the game manual `rules.htm?rulespage=training` lists "Fitness | Endurance, power" / "Strength | Power, endurance", matched by the workbook's DB tab; the workbook's Refs!I26:Q37 seed table has those two rows TRANSPOSED — per-row SUM totals 255/270 survive the swap, so cross-checking totals can't catch it). Aging-path program picks (endurance<5→fitness, power<5→strength) therefore target each program's STRONG skill. The community senior schedule's SECOND fielding stage (to 11/12, pace/wrist 11 else 12) is gated `age < 25` so it can't pre-empt the 25-29 Strength/Endurance phase ("mainly strength after 25"); keeper youth-curve technique catch-up uses `keeperbatting` (not battingtech — matches `TRAINABLE.technique`).
- **Match Data paste box**: only on `teamfixtures.htm` (`pageType === 'matches'`). Deliberately NO on-screen match report — the paste only feeds history for Match Orders/Ground evidence (user explicitly removed the report; don't re-add without being asked). Accepts commentary-page text (preferred — the only source carrying pitch+weather+format every time), tab scorecards and scorecard HTML; Export/Import JSON (history lives in GM storage, lost on reinstall). Imports bypass the parsers, so `sanitizeImportedMatch` strips markup/whitelists enums. History↔squad matching uses `playerNameKey` (initial + surname — squads show full names, scorecards "B. Melchiot"); keys shared by two squad-mates are skipped. Conditions evidence needs ≥2 matches/5 overs.
- **★ Overall Rating calibration** (the user buys on it alone): quality = projected skill-sum ×55/80 (1:1 cap-at-55, then /70, both tied the best youth prospects at max — projections reach ~75); wage value = (skill-sum per $1k − 10)×0.6, weight ×0.4 (the old mapping saturated for every real wage; at ×0.8 it outweighed a skill tier). `breakdown` is populated and shown as the badge tooltip — keep every term explainable. Sturdy weighs 1.5 at ≤20 and 28+, 0.75 at 21-27 (`talentWeight`, user/community data) everywhere talents are counted.
- **Squad page**: only the grid view (squadViewId=2) has skills; the default summary view scrapes all-zero stats. `init()` skips saving a skill-less scrape and force-refetches. Opponent pages have reduced columns — `fetchSquadFromPage` auto-picks the parser per row.
